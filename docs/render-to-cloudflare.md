# Move RI BUROM from Render to Cloudflare Workers Free

**Status on 25 November 2026** · Compatibility staging, password-protected full application staging, and the separate SELECT-only Cloudflare production-data comparison Worker have deployed and passed their hosted checks. The isolated application staging has passed seven synthetic business workflows, including Cloudinary upload and public CDN delivery, plus sitemap parity checks. Both staging and comparison have no email schedule; only Render serves the live domain and its production notification outbox. No production cutover is approved. See [production readiness gates](cloudflare-cutover-readiness.md).

## Hosting and services

| Component | Destination |
| --- | --- |
| Website and Control Room | Cloudflare Workers Free serves tracked static assets and forwards dynamic requests to the existing Flask WSGI app in a SQLite-backed Durable Object. Durable Object SQLite holds rate limits and test state. [Flask on Workers](https://developers.cloudflare.com/workers/languages/python/packages/flask/) |
| Scheduled email | A Cloudflare Cron Trigger invokes the same Durable Object to drain a bounded batch from the PostgreSQL notification outbox. Brevo remains the mail provider. [Cron Triggers](https://developers.cloudflare.com/workers/configuration/cron-triggers/) |
| Database | Retain the existing Neon PostgreSQL production database and connect through Hyperdrive. Keep the Hyperdrive query cache disabled so staff see their writes immediately. Review attachment bytes also live in Neon. D1 would require a PostgreSQL-to-SQLite application and data migration. [Python Hyperdrive](https://developers.cloudflare.com/hyperdrive/examples/python-workers/) · [D1 limits](https://developers.cloudflare.com/d1/platform/limits/) |
| Photos, PDFs and other public media | Keep Cloudinary, existing asset IDs, delivery URLs and permissions. R2's free allowance can incur overages, so leave it disabled under the zero-charge requirement. [R2 pricing](https://developers.cloudflare.com/r2/pricing/) |
| Public domain and mail DNS | Retain the registrar, domain, canonical redirects and mail provider. Preserve MX, SPF, DKIM, DMARC, sender verification and search verification records. |

Hyperdrive on Workers Free allows 100,000 database statements per day. The public Worker and Durable Object each have their own free-plan quotas. Measure usage with representative traffic and account for the daily reset and errors at quota exhaustion. Use standard Linux GitHub runners within the included Actions minutes and verify the remaining allowance before manual re-runs. Keep all providers on their existing free tiers. [Workers limits](https://developers.cloudflare.com/workers/platform/limits/) · [Durable Object pricing](https://developers.cloudflare.com/durable-objects/platform/pricing/) · [Hyperdrive pricing](https://developers.cloudflare.com/hyperdrive/platform/pricing/) · [Actions billing](https://docs.github.com/en/billing/concepts/product-billing/github-actions)

1. Attach the canonical domain to the verified production Worker. Confirm the `www` redirect, certificate, HTTPS and correct hostname before admitting general traffic. If a temporary Workers Route provides quick rollback over the existing proxied Render DNS record, confirm the Worker serves Flask itself and never forwards site traffic to Render during the switch. [Workers Routes](https://developers.cloudflare.com/workers/configuration/routing/routes/) · [Worker Custom Domains](https://developers.cloudflare.com/workers/configuration/routing/custom-domains/)
2. Verify public pages, staff login, Neon readiness, known media and invoice access through the canonical hostname. Disable the Render email consumer and allow in-flight claims to finish or expire. **Only after the owner approves the handoff**, explicitly set `RIBUROM_LIVE_OUTBOX_APPROVED=true`, require `RIBUROM_HOST=riburomtours.com`, and enable the production Cloudflare Cron with `OUTBOX_SCHEDULED=true`. The runtime refuses to run production notification jobs without all three settings or if staging/readonly protections are active. Submit one agreed test enquiry and verify database state, Brevo delivery and retry handling. The Worker always disables the web process's background thread. Compare queue age and failed jobs before and after the handoff.
3. Watch application errors, latency, database and provider usage, and delivery backlog through normal traffic and an idle/retry cycle. Record the deployed Worker version, Git SHA, schema revision, elapsed recovery test and routing changes.

## 4. Roll back or retire Render

Roll back for sustained readiness failures, lost enquiry writes, broken staff access, private data exposure or a delivery backlog that the new scheduler cannot clear. Disable the Cloudflare consumer and restore the saved Render route and outbox. Check the latest accepted enquiry, protected media and email delivery. Both platforms use the same Neon database, so an application-host rollback normally needs no database restore. Reconcile the Brevo log before manually replaying delivery attempts.

After production acceptance, confirm that the permanent Cloudflare Custom Domain and the **sole active** Cloudflare outbox scheduler operate independently. Keep the Render web service provisioned and recoverable as the rollback host; its outbox consumer must remain disabled during the Cloudflare live-email phase. **Do not delete, suspend or retire Render** or its domain records without a separate explicit owner authorization after an agreed stabilization period.
